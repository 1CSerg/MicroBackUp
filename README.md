# MicroBackUp

Простая кроссплатформенная консольная утилита для инкрементального резервного копирования. Утилита использует формат 7z (библиотека `py7zr`) и поддерживает разбиение архива на тома и установку пароля.

Удобна для бэкапа в облачные хранилища (например, Облако Mail): `dest` можно указать на синхронизируемую папку клиента, а `--split` подобрать под лимит размера файла в облаке. Пароль защищает архив на стороне облака, инкрементальность не гоняет в облако неизменённые данные.

## Особенности
- **Инкрементальность**: перед созданием архива утилита проверяет, изменились ли исходные файлы. Для этого она использует файл `ИмяАрхива_hash.json`, в котором сохраняет количество файлов/папок, хеш имён файлов и хеш содержимого. Проверки выполняются лениво (последовательно), чтобы сэкономить ресурсы.
- **Облачные хранилища**: тома и пароль позволяют укладываться в лимиты облака и не отдавать туда архив в открытом виде. Папку назначения можно направить в каталог синхронизации (Облако Mail и аналоги).
- **Кроссплатформенность**: работает на Windows и Linux.
- **Логирование**: вывод в консоль и опционально в файл с ротацией по размеру.
- **Один исполняемый файл**: можно скомпилировать в один `.exe` файл (или бинарник для Linux) с помощью PyInstaller.

## Требования
- Python 3.8+ (если запускать из исходников)
- Зависимости из `requirements.txt`

## Установка зависимостей
```bash
pip install -r requirements.txt
```

## Использование

```bash
python main.py -s <пути_к_источникам> -d <папка_назначения> -n <имя_архива> [--split <размер_тома>] [-p <пароль>]
```

Либо запуск по конфигурационному файлу:

```bash
python main.py -c MicroBackUp.conf
```

### Аргументы
- `-v`, `--version`: Показать номер версии программы и выйти.
- `-c`, `--config` (опциональный): Путь к INI-файлу с заданиями резервного копирования. Если указан, аргументы `-s`/`-d`/`-n`/`--split`/`-p` не используются; параметры `--log-*` перекрывают значения из `[GLOBAL]`.
- `-s`, `--sources` (обязательный без `-c`): Список исходных файлов или папок для резервного копирования (через пробел).
- `-d`, `--dest` (обязательный без `-c`): Папка назначения, куда будет сохранен архив и файл с хешами.
- `-n`, `--name` (обязательный без `-c`): Имя архива (без расширения).
- `--split` (опциональный): Размер тома для разбиения архива. Поддерживаются суффиксы `k` (килобайты), `m` (мегабайты), `g` (гигабайты). Например: `100m`, `1.5g`.
- `-p`, `--password` (опциональный): Пароль для архива.
- `--hide` (опциональный, только для Windows): Скрывает окно консоли сразу после запуска программы. Удобно для запуска по расписанию, если EXE собран в консольном режиме.
- `--log-file` (опциональный): Путь к файлу лога. Без `-c`: если не указан, лог пишется только в консоль. С `-c`: путь берётся из `[GLOBAL]`, этот аргумент его перекрывает.
- `--log-level` (опциональный): Уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR` (также принимается `CRITICAL`). По умолчанию `INFO`.
- `--log-max-size` (опциональный): Размер файла лога, при достижении которого выполняется ротация. Поддерживаются суффиксы `k`, `m`, `g`. Например: `5m`. Если не задан, ротация не выполняется.
- `--log-backup-count` (опциональный): Сколько старых копий лога хранить после ротации (`имя.log.1`, `имя.log.2`, …). По умолчанию `3`.

### Примеры
Создать архив `my_backup.7z` из папок `docs` и `images`, сохранить в `D:\backups`:
```bash
python main.py -s docs images -d D:\backups -n my_backup
```

Создать архив с паролем `secret` и разбить на тома по 500 МБ:
```bash
python main.py -s docs -d D:\backups -n my_backup --split 500m -p secret
```

Запустить несколько заданий из конфига:
```bash
python main.py -c MicroBackUp.conf
```

## Конфигурационный файл

Файл в формате INI. Секция `[GLOBAL]` задаёт значения по умолчанию для `split`, `password` и параметров логирования. Любые другие секции описывают отдельные задания.

В каждой секции задания обязательны `sources`, `dest` и `name`. Поля `split` и `password` в секции задания перекрывают глобальные. Пути с пробелами в `sources` нужно заключать в кавычки.

Параметры логирования читаются только из `[GLOBAL]`. Явно указанные аргументы `--log-*` перекрывают соответствующие поля; если аргумент не передан, остаётся значение из конфига.
- `log_file` — путь к файлу лога. Если параметр отсутствует или пустой, лог в файл не пишется. Отключить запись в файл через CLI, когда путь уже задан в конфиге, нельзя: `--log-file` только задаёт или меняет путь.
- `log_level` — уровень: `DEBUG`, `INFO`, `WARNING`, `ERROR` (также принимается `CRITICAL`). По умолчанию `INFO`.
- `log_max_size` — размер, при котором лог подрезается (ротация). Например: `5m`. Если не задан, файл растёт без ротации.
- `log_backup_count` — число хранимых старых копий лога. По умолчанию `3`.

Лог всегда выводится в консоль. Если задан `log_file`, те же сообщения пишутся и в файл. Сообщения `WARNING` и `ERROR` идут в stderr, остальные — в stdout. В файле используется формат с датой и уровнем (`%(asctime)s - %(levelname)s - %(message)s`).

Пример `MicroBackUp.conf`:

```ini
[GLOBAL]
split = 100m
password = my_global_secret
log_file = MicroBackUp.log
log_level = INFO
log_max_size = 5m
log_backup_count = 3

[ProjectA]
sources = "D:\Work\Project A" C:\Logs
dest = D:\Backups\ProjectA
name = proj_a_backup

[ProjectB]
sources = D:\Work\ProjectB
dest = D:\Backups\ProjectB
name = proj_b_backup
split = 500m
password = specific_secret
```

## Сборка в исполняемые файлы (EXE)

Для создания независимых исполняемых файлов на Windows используйте скрипт сборки. Вы можете запустить его двумя способами:

1. Двойным кликом по файлу `build.ps1` (если в Windows разрешен запуск PowerShell-скриптов) или через консоль:
   ```powershell
   .\build.ps1
   ```
2. Либо напрямую через Python:
   ```bash
   python build.py
   ```

Скрипт использует `PyInstaller` (убедитесь, что он установлен: `pip install pyinstaller`). 
После успешной сборки в папке `dist` появятся два файла:
1. `MicroBackUp.exe` — стандартная версия. При запуске открывает окно консоли, где виден прогресс и возможные ошибки. Удобна для ручного запуска.
2. `MicroBackUp-bg.exe` — фоновая ("тихая") версия. Окно консоли не появляется вообще. Идеально подходит для запуска бэкапов по расписанию через планировщик задач. Рекомендуется запускать с `-c` и заданным `log_file`, иначе ход работы нигде не будет виден.

# MicroBackUp

Простая кроссплатформенная консольная утилита для полного резервного копирования с умным пропуском неизмененных данных. Утилита использует формат 7z: по умолчанию встроенную библиотеку `py7zr`, опционально — внешнюю утилиту 7-Zip (намного быстрее). Поддерживаются разбиение архива на тома, степень сжатия и пароль.

Удобна для бэкапа в облачные хранилища (например, Облако Mail): `dest` можно указать на синхронизируемую папку клиента, а `--split` подобрать под лимит размера файла в облаке. Пароль защищает архив на стороне облака, умный пропуск не гоняет в облако неизменённые данные.

## Особенности
- **Умный пропуск неизмененных данных**: перед созданием полного архива утилита проверяет, изменились ли исходные файлы. Если изменений нет, создание архива пропускается. Для этого она использует файл `ИмяАрхива_hash.json`, в котором сохраняет количество файлов/папок, хеш имён и хеш метаданных (размер и mtime). Полный хеш содержимого считается только при `check_content_hash` / `--check-content-hash`. Проверки выполняются лениво (последовательно), чтобы сэкономить ресурсы.
- **Облачные хранилища**: тома и пароль позволяют укладываться в лимиты облака и не отдавать туда архив в открытом виде. Папку назначения можно направить в каталог синхронизации (Облако Mail и аналоги).
- **Кроссплатформенность**: работает на Windows и Linux.
- **Логирование**: вывод в консоль и опционально в файл с ротацией по размеру.
- **Внешний 7-Zip**: если в конфиге задан `sevenzip_path`, архив собирает оригинальная утилита 7z; при ошибке программа откатится на встроенный движок.
- **Один исполняемый файл**: можно скомпилировать в один `.exe` файл (или бинарник для Linux) с помощью PyInstaller.

## Требования
- Python 3.10+ (если запускать из исходников)
- Зависимости из `requirements.txt` (запуск из исходников), `requirements-build.txt` (сборка exe), `requirements-dev.txt` (тесты).

## Сборка в исполняемые файлы (EXE)

Для создания независимых исполняемых файлов на Windows используйте скрипт сборки. Вы можете запустить его двумя способами:

1. Двойным кликом по файлу `build.bat` (или `build.ps1`, если в Windows разрешен запуск PowerShell-скриптов) либо через консоль:
   ```cmd
   build.bat
   ```
2. Либо напрямую через Python:
   ```bash
   python build.py
   ```

`build.bat` и `build.ps1` сами ставят зависимости из `requirements-build.txt` (runtime-пакеты и `PyInstaller`) и запускают сборку. При запуске через `python build.py` недостающий `PyInstaller` тоже ставится автоматически.
После успешной сборки в папке `dist` появятся два файла:
1. `MicroBackUp.exe` — стандартная версия. При запуске открывает окно консоли, где виден прогресс и возможные ошибки. Удобна для ручного запуска.
2. `MicroBackUp-bg.exe` — фоновая ("тихая") версия. Окно консоли не появляется вообще. Идеально подходит для запуска бэкапов по расписанию через планировщик задач. Рекомендуется задать `log_file` в конфиге (или `--log-file`), иначе ход работы нигде не будет виден. Если рядом с exe нет `MicroBackUp.conf`, фоновая сборка создаст шаблон и завершится — без окна это можно увидеть только в логе.

## Использование

### Установка зависимостей

```bash
pip install -r requirements.txt
```

### Запуск Python версии

```bash
python main.py -s <пути_к_источникам> -d <папка_назначения> -n <имя_архива> [--split <размер_тома>] [-p <пароль>]
```

Либо запуск по конфигурационному файлу:

```bash
python main.py -c MicroBackUp.conf
```

### Автопоиск конфига

Если не указаны ни `-c`, ни `-s`/`-d`/`-n`, программа ищет файл `MicroBackUp.conf` в каталоге с собой (рядом с `.exe` для собранной версии, рядом с `main.py` при запуске из исходников).

- Файл найден — задания выполняются из него.
- Файла нет — программа создаёт его, заполняет **закомментированными** примерами всех опций, пишет путь в лог и завершается с кодом 0. Раскомментируйте и заполните нужные поля, затем запустите снова.

Явно указанный `-c путь` этот автопоиск не заменяет: отсутствующий файл в этом случае — ошибка.

### Аргументы
- `-v`, `--version`: Показать номер версии программы и выйти.
- `-c`, `--config` (опциональный): Путь к INI-файлу с заданиями резервного копирования. Если указан, аргументы `-s`/`-d`/`-n` не используются как задание; `--split`/`-p`/`--compression-level`/`--sevenzip-*` и `--log-*` перекрывают значения из конфига.
- `-s`, `--sources` (обязательный без `-c` и без автоконфига): Список исходных файлов или папок для резервного копирования (через пробел).
- `-d`, `--dest` (обязательный без `-c` и без автоконфига): Папка назначения, куда будет сохранен архив и файл с хешами.
- `-n`, `--name` (обязательный без `-c` и без автоконфига): Имя архива (без расширения).
- `--split` (опциональный): Размер тома для разбиения архива. Поддерживаются суффиксы `k` (килобайты), `m` (мегабайты), `g` (гигабайты). Например: `100m`, `1.5g`.
- `-p`, `--password` (опциональный): Пароль для архива. Внимание: пароль, переданный через CLI, виден в списке процессов (`ps`, Process Explorer) другим пользователям машины. Если `-p` не передан, пароль берётся из конфига или из переменной окружения `MICROBACKUP_PASSWORD` (приоритет: CLI `-p` > `password` в секции задания > env `MICROBACKUP_PASSWORD` > `password` в `[GLOBAL]`). Явный пустой `password =` в секции отключает пароль для этого задания. Для плановых задач предпочитайте пароль в переменной окружения или в конфигурационном файле (см. ниже предупреждение о хранении).
- `--compression-level` (опциональный): Степень сжатия 0–9. `0` — хранение без сжатия, `1` — самое быстрое, `5` — типичный дефолт 7-Zip, `9` — максимальное сжатие. Действует и на встроенный движок, и на внешний 7z. Если не задан, каждый движок использует свой дефолт.
- `--sevenzip-path` (опциональный): Путь к `7z.exe` / `7z`. Если не задан, используется встроенная библиотека `py7zr`.
- `--sevenzip-args` (опциональный): Дополнительные ключи только для внешнего 7z (например `-mmt=4`).
- `--hide` (опциональный, только для Windows): Скрывает окно консоли сразу после запуска программы. Удобно для запуска по расписанию, если EXE собран в консольном режиме.
- `--log-file` (опциональный): Путь к файлу лога. Без `-c`: если не указан, лог пишется только в консоль. С `-c`: путь берётся из `[GLOBAL]`, этот аргумент его перекрывает.
- `--log-level` (опциональный): Уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR` (также принимается `CRITICAL`). По умолчанию `INFO`.
- `--log-max-size` (опциональный): Размер файла лога, при достижении которого выполняется ротация. Поддерживаются суффиксы `k`, `m`, `g`. Например: `5m`. Если не задан, ротация не выполняется.
- `--log-backup-count` (опциональный): Сколько старых копий лога хранить после ротации (`имя.log.1`, `имя.log.2`, …). По умолчанию `3`.
- `--check-content-hash` (опциональный): Принудительно проверять хеши содержимого файлов, а не только метаданные (размер и время изменения). При использовании с `-c/--config` применяется как значение по умолчанию для секций, в которых `check_content_hash` не задан явно — то есть секция с `check_content_hash = false` сохраняет быстрый режим, даже если флаг передан в CLI.

### Примеры
Создать архив `my_backup.7z` из папок `docs` и `images`, сохранить в `D:\backups`:
```bash
python main.py -s docs images -d D:\backups -n my_backup
```

Создать архив с паролем `secret` и разбить на тома по 500 МБ:
```bash
python main.py -s docs -d D:\backups -n my_backup --split 500m -p secret
```

Запустить несколько заданий из конфига:
```bash
python main.py -c MicroBackUp.conf
```
При первом запуске без аргументов программа сама создаст `MicroBackUp.conf` рядом с собой. Либо скопируйте шаблон: `copy MicroBackUp.conf.example MicroBackUp.conf` на Windows или `cp MicroBackUp.conf.example MicroBackUp.conf` на Linux, затем отредактируйте под себя.

## Конфигурационный файл

Файл в формате INI. Секция `[GLOBAL]` задаёт значения по умолчанию для `split`, `password`, `exclude`, `compression_level`, `sevenzip_path`, `sevenzip_args` и параметров логирования. Любые другие секции описывают отдельные задания. Секция `[DEFAULT]` не используется: стандартное INI-наследование отключено, такая секция игнорируется.

В каждой секции задания обязательны `sources`, `dest` и `name`. Поля `split`, `password`, `check_content_hash`, `compression_level`, `sevenzip_path` и `sevenzip_args` в секции задания перекрывают глобальные. Поле `exclude` в секции **дописывается** после глобального списка (см. ниже). Пути с пробелами в `sources` нужно заключать в кавычки. Кавычки вокруг `dest` необязательны (в том числе для путей с пробелами) и снимаются автоматически.

> **Пустой пароль в секции.** Если в `[GLOBAL]` задан `password`, а в конкретной секции нужно создать архив без пароля, задайте в секции `password =` (пустое значение) — это явно отключит пароль для этой секции. Если же ключ `password` в секции отсутствует полностью, будет унаследован глобальный пароль.

> **Предупреждение о пароле в конфиге.** Поле `password` хранится открытым текстом. Не помещайте конфиг с паролем в публичные репозитории, не отправляйте его в облако в открытом виде и ограничьте доступ к файлу на уровне ОС. Альтернатива — передавать пароль через переменную окружения `MICROBACKUP_PASSWORD` (приоритет: CLI `-p` > `password` в секции задания > env `MICROBACKUP_PASSWORD` > `password` в `[GLOBAL]`). Явный пустой пароль в секции (`password =`) отключает пароль для этой секции, перекрывая и env, и глобальное значение. В `*_hash.json` рядом с архивом хранится не пароль, а солёный PBKDF2-хеш — только чтобы заметить смену пароля. Шаблон конфига `MicroBackUp.conf.example` отслеживается в git; сам `MicroBackUp.conf` добавлен в `.gitignore`, чтобы случайно не закоммитить реальные секреты.

Параметры логирования читаются только из `[GLOBAL]`. Явно указанные аргументы `--log-*` перекрывают соответствующие поля; если аргумент не передан, остаётся значение из конфига.
- `log_file` — путь к файлу лога. Если параметр отсутствует или пустой, лог в файл не пишется. Отключить запись в файл через CLI, когда путь уже задан в конфиге, нельзя: `--log-file` только задаёт или меняет путь.
- `log_level` — уровень: `DEBUG`, `INFO`, `WARNING`, `ERROR` (также принимается `CRITICAL`). По умолчанию `INFO`.
- `log_max_size` — размер, при котором лог подрезается (ротация). Например: `5m`. Если не задан, файл растёт без ротации.
- `log_backup_count` — число хранимых старых копий лога. По умолчанию `3`. Допустимы неотрицательные целые; при `0` старые копии не сохраняются (при ротации активный файл обрезается, предыдущие удаляются).
- `check_content_hash` — проверять хеши содержимого файлов (true/false). По умолчанию `false`.
- `compression_level` — степень сжатия 0–9. `0` — без сжатия (store), выше — сильнее и медленнее. Действует на оба движка. Если ключ не задан, каждый движок использует свой дефолт (`-mx=5` у 7z, стандартная цепочка LZMA2 у py7zr). Пустое значение или `none`/`off` в секции задания возвращает дефолт движка, перекрывая `[GLOBAL]`. Архивы разных движков при одном уровне **не** идентичны побайтно. Смена уровня сама по себе **не** вызывает пересборку — удалите `*_hash.json`, если нужно перепаковать уже существующий архив.

### Внешний 7-Zip

Встроенная библиотека `py7zr` работает медленнее оригинального 7-Zip. Чтобы создавать архив внешней утилитой, задайте путь:

- `sevenzip_path` — путь к `7z.exe` (Windows, например `C:\Program Files\7-Zip\7z.exe`) или `7z` (Linux, например `/usr/bin/7z`). Используется только если задан явно: программа не ищет 7z в PATH, пока значение не является голым именем (`7z`). Пустое значение / `none` / `off` в секции отключает внешний 7z для этой секции.
- `sevenzip_args` — дополнительные ключи только для внешнего 7z (например `-mmt=4`). Игнорируются встроенным движком.

Приоритет: CLI `--sevenzip-path` / `--sevenzip-args` > секция задания > `[GLOBAL]`.

Если бинарник не найден, не запускается или 7z вернул ошибку, в лог пишется предупреждение и архив собирается встроенным `py7zr` (с тем же `compression_level`). Внешний 7z также не используется, если у двух источников совпадают имена корней (встроенный движок их переименовывает, 7z в одном вызове склеил бы их).

Тома внешнего 7z имеют суффиксы `.7z.001`, `.002`, …; встроенный движок при split даёт `.7z.0001`. Программа понимает оба варианта.

Если заданы и пароль, и внешний 7z, пароль передаётся 7z в командной строке и может быть виден в списке процессов. У встроенного движка этой проблемы нет.

### Исключение путей (`exclude`)

Ключ `exclude` задаёт пути, которые не попадают в архив и не участвуют в проверке изменений. Синтаксис как в `.gitignore`: один паттерн на строку, продолжения строк с отступом (стандартный многострочный INI).

Паттерны сопоставляются **относительно корня каждого источника** из `sources`. Для `sources = "D:\Work\Project A"` паттерн `build/` исключает `D:\Work\Project A\build`. Тот же набор паттернов применяется к каждому источнику секции независимо.

Поддерживаются:
- маски `*`, `?`, `**`, классы символов `[abc]`;
- `/` в конце паттерна — только каталог (`build/` не исключит файл с именем `build`);
- `/` в начале — привязка к корню источника (`/root_only` не совпадёт с `sub/root_only`);
- `!` в начале — вернуть путь, исключённый предыдущим правилом.

Правила из `[GLOBAL]` идут первыми, правила секции дописываются после. Секция может отменить глобальное правило через `!паттерн`.

На Windows сопоставление **без учёта регистра**, на Linux — с учётом (как у файловой системы).

Исключённый каталог не обходится: файлы внутри него не читаются, и `!` внутри такого каталога **не** возвращает их (как в git). Сам корень источника из `sources` исключить нельзя — уберите его из `sources`. Если в каталоге все файлы исключены, пустой каталог всё равно остаётся в архиве.

Комментарии `#` внутри значения INI отбрасывает сам `configparser`, а не gitignore-парсер. Чтобы исключить файл, имя которого начинается с `#`, экранируйте решётку: `\#имя`.

Лог всегда выводится в консоль. Если задан `log_file`, те же сообщения пишутся и в файл. Сообщения `WARNING` и `ERROR` идут в stderr, остальные — в stdout. В файле используется формат с датой и уровнем (`%(asctime)s - %(levelname)s - %(message)s`).

Пример `MicroBackUp.conf` (шаблон `MicroBackUp.conf.example` в репозитории — скопируйте его в `MicroBackUp.conf` и заполните):

```ini
[GLOBAL]
split = 100m
password = <your_password>
log_file = MicroBackUp.log
log_level = INFO
log_max_size = 5m
log_backup_count = 3
compression_level = 5
sevenzip_path = C:\Program Files\7-Zip\7z.exe
sevenzip_args = -mmt=on
exclude =
    *.tmp
    ~$*

[ProjectA]
sources = "D:\Work\Project A" C:\Logs
dest = D:\Backups\ProjectA
name = proj_a_backup
exclude =
    node_modules/
    build/
    *.log
    !important.log

[ProjectB]
sources = D:\Work\ProjectB
dest = D:\Backups\ProjectB
name = proj_b_backup
split = 500m
password = <your_password>
compression_level = 9
```
